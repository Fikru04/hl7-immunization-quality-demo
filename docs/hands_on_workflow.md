# Anonymized hands-on workflow

This page explains how the public demonstration maps to the type of work I
perform as a Public Health Informaticist. It intentionally omits jurisdiction,
vendor, organization, project, and implementation-guide identifiers.

| Professional activity | Public demonstration equivalent |
|---|---|
| Review an immunization implementation guide | Define a small, explicit set of message-review rules |
| Create a positive test message | Include a complete synthetic VXU-like message |
| Create a negative test message | Remove a required segment or introduce an unexpected value |
| Define expected validation behavior | Document the finding expected from each scenario |
| Compare expected and actual behavior | Run the script and inspect the CSV output |
| Investigate a defect or false result | Add a focused unit test and document the limitation |
| Coordinate with technical and public-health stakeholders | Use clear issue flags that can be discussed across roles |
| Support formal tooling and reporting | Relate the exercise to IGAMT, P-ACT, and CAART without copying restricted artifacts |

## Professional experience summary

I have supported immunization interoperability work across multiple
jurisdictional environments and technology partners. Because those engagements
are confidential, this repository uses only the generalized description
“multiple jurisdictions and technology partners” rather than public names or
project identifiers.

The work represented includes HL7 v2.5.1 message creation and interpretation,
implementation-guide review, test planning, expected-result analysis,
stakeholder coordination, interoperability testing, and data-quality assessment.
